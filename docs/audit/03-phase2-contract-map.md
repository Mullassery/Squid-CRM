## What was captured

- Data schema: 716 types. Metadata/auth: 656. Admin: 109.
- OpenAPI core: 330 paths / 123 component schemas. OpenAPI metadata: 27 paths / 67 schemas.
- `client-config.json` and nine REST/GraphQL example pairs.
- v2.50.0 vs v2.49.0: data and admin SDL unchanged; metadata adds
  `ApplicationPreferences`, workspace credit fields and `CUSTOM_ROLES`, and
  removes two feature flags. OpenAPI paths and schemas unchanged. Example UUIDs
  differ by construction.

The capture script now calls `activateWorkspace(data: {})` after workspace
creation; without it the data schema only contains 97 types instead of 716.

## Frontend operation coverage (schema level)

| Document set | Operations | FULL | PARTIAL | MISSING |
| --- | ---: | ---: | ---: | ---: |
| `generated/graphql.ts` | 36 | 0 | 0 | 36 |
| `generated-metadata/graphql.ts` | 325 | 38 | 2 | 285 |

Findings:

- The static data document only contains workflow, timeline, agent and search
  operations. Core object CRUD is built dynamically from metadata at runtime,
  so it is covered by the dynamic-object gaps already in the migration matrix,
  not by these 36 documents.
- The 38 FULL metadata operations cover the view, metadata-item, API-key and
  auth flows already implemented. `SignUp` and `SignOut` are PARTIAL only
  because our schema lacks optional upstream arguments (`captchaToken`,
  `locale`, `verifyEmailRedirectPath`, `refreshToken`).
- The 285 MISSING metadata operations are the Phase 5/6 backlog: roles,
  permissions, webhooks, page layouts, workflow/admin, applications and agents.

## Reproduce

```bash
# 1. Golden contracts from the pinned source
TWENTY_IMAGE=squid-twenty:v2.50.0-pinned \
  APP_SECRET=$(openssl rand -hex 32) \
  ENCRYPTION_KEY=$(openssl rand -hex 32) \
  docker compose -p twenty-capture-v250 \
  -f reference/capture/docker-compose.yml up -d
python3 scripts/capture-contracts.py --tag v2.50.0 --out contracts/v2.50.0
python3 scripts/capture-examples.py --tag v2.50.0

# 2. Operation maps (requires a running Squid server for introspection)
DATABASE_URL=postgres://... APP_SECRET=... BIND_ADDR=127.0.0.1:3111 \
  cargo run -p squid-server
python3 scripts/map-frontend-operations.py --squid-url http://127.0.0.1:3111
python3 scripts/map-rest-routes.py
```

Schema-level FULL means every selected field/argument resolves; runtime values,
input-object completeness and business semantics are tracked separately.
